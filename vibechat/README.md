# VibeChat — случайный видеочат 1 на 1

Пользователь подтверждает 18+, нажимает «Начать» и через секунду видит случайного собеседника. Видео и звук идут напрямую между браузерами по WebRTC, сервер только подбирает пары, передаёт сигнализацию и текстовый чат. Название меняется одной переменной `APP_NAME`.

| Запуск в production-режиме | стартует, отдаёт HSTS/CSP, вход администратора работает |

## Стек

- **Клиент:** React 19, TypeScript, Tailwind CSS v4, сборка через esbuild (`scripts/build-client.mjs`).
- **Сервер:** Node.js 22, TypeScript, встроенный `node:http`, WebSocket (`ws`) для сигнализации, `zod` для валидации.
- **Данные:** SQLite, встроенный в Node (`node:sqlite`), миграции в `server/migrations`.
- **Медиа:** WebRTC, STUN, TURN (coturn или облачный) через переменные окружения.
- **Тесты:** встроенный `node:test` + Playwright для сквозного теста.

Зависимостей в рантайме две: `ws` и `zod`.

> **Почему не Vite / Express / Socket.IO / Prisma / PostgreSQL.** В среде разработки был закрыт доступ к npm-реестру, а приложение нужно было реально собрать и проверить. Выбран стек, который удалось полностью проверить: esbuild (на нём же работает Vite), `ws` вместо Socket.IO, встроенный SQLite вместо PostgreSQL. Хранилище скрыто за интерфейсом `Storage` (`server/src/storage/types.ts`), транспорт — за интерфейсом `Connection`, поэтому PostgreSQL или Socket.IO подключаются без переписывания логики.

## Локальный запуск

Нужен **Node.js 22.13+**.

```bash
npm install
cp .env.example .env          # для разработки можно ничего не менять
npm run dev                   # http://localhost:8080
```

Чтобы проверить звонок на одном компьютере, откройте сайт в двух разных браузерах (или в обычном и инкогнито-окне) и нажмите «Начать» в обоих.

**С телефона.** Браузеры дают доступ к камере только по HTTPS (исключение — `localhost`). Для теста с телефона пробросьте локальный сервер через HTTPS-туннель:

```bash
npx cloudflared tunnel --url http://localhost:8080
# или: ngrok http 8080
```

Затем добавьте выданный адрес в `.env`: `EXTRA_ORIGINS=https://xxxx.trycloudflare.com`.

**Администратор:**

```bash
npm run admin:create -- admin       # спросит пароль (от 12 символов)
```

Панель модерации: `http://localhost:8080/admin`.

**Проверки:**

```bash
npm run typecheck
npm test
npm run build && npx playwright install chromium && npm run test:e2e && npm run test:browser
```

**Production-сборка без Docker:**

```bash
npm run build
NODE_ENV=production npm start     # переменные берутся из .env
```

## Развёртывание в интернете

### Вариант 1: свой VPS (рекомендуется)

Один сервер с Docker поднимает всё: приложение, HTTPS и свой TURN.

1. Арендуйте VPS (Hetzner, DigitalOcean, Timeweb, Selectel и т. п.), 1–2 vCPU / 2 ГБ RAM для старта, публичный IPv4.
2. Направьте DNS-запись `A` вашего домена на IP сервера.
3. Откройте порты: `80/tcp`, `443/tcp`, `443/udp`, `3478/tcp+udp`, `49160–49400/udp`.
4. Скопируйте проект на сервер и заполните `.env`:

   ```env
   NODE_ENV=production
   APP_NAME=VibeChat
   DOMAIN=vibechat.example.com
   PUBLIC_ORIGIN=https://vibechat.example.com
   PUBLIC_IP=203.0.113.10
   SESSION_SECRET=<node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))">
   TURN_SECRET=<ещё одна случайная строка>
   TURN_URLS=turn:vibechat.example.com:3478?transport=udp,turn:vibechat.example.com:3478?transport=tcp
   SUPPORT_EMAIL=support@example.com
   ADMIN_BOOTSTRAP_USERNAME=admin
   ADMIN_BOOTSTRAP_PASSWORD=<надёжный пароль>
   ```

5. Запустите:

   ```bash
   docker compose -f docker-compose.prod.yml up -d --build
   ```

   Caddy автоматически получит сертификат Let's Encrypt. После первого входа в `/admin` удалите `ADMIN_BOOTSTRAP_*` из `.env`.

6. Проверьте: `https://ваш-домен/readyz` → `{"ok":true}`. TURN можно проверить на <https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/> (нужен временный логин — откройте `https://ваш-домен/api/ice` в браузере после входа в чат).

Если у вас уже есть Nginx — используйте `deploy/nginx.conf.example` и `TRUST_PROXY=1`.

### Вариант 2: PaaS (Render, Railway, Fly.io)

- Сборка: `npm install && npm run build`, запуск: `npm start`, порт — из `PORT`.
- Подключите постоянный диск и укажите `DATA_DIR` на него (иначе жалобы и баны сотрутся при перезапуске).
- WebSocket должен быть разрешён (на этих платформах он работает по умолчанию).
- `TRUST_PROXY=1`, `PUBLIC_ORIGIN` — ваш домен.
- TURN на PaaS не поднять — используйте облачный: Metered.ca, Twilio Network Traversal, Cloudflare Calls TURN, Xirsys. Укажите `TURN_URLS`, `TURN_USERNAME`, `TURN_CREDENTIAL`.

### Что потребует денег

| Ресурс | Нужен ли | Ориентир |
|---|---|---|
| Домен | да | ~$10/год |
| VPS для приложения | да | от ~$5–10/мес |
| TURN-трафик | да, для 10–20% звонков | свой coturn — трафик VPS; облачные — от ~$0,4/ГБ. Один час видео через TURN ≈ 0,5–1 ГБ |
| `ICE_TRANSPORT_POLICY=relay` | по желанию | весь трафик через TURN — в 5–10 раз больше расходов на трафик |
| Cloudflare Turnstile | по желанию | бесплатно |
| Мониторинг | по желанию | UptimeRobot / Grafana Cloud — есть бесплатные тарифы |

### Что настроить вручную

- DNS домена и порты на сервере.
- `SESSION_SECRET`, `TURN_SECRET`, пароль администратора.
- Cloudflare Turnstile: создайте виджет в панели Cloudflare и укажите `TURNSTILE_SITE_KEY` и `TURNSTILE_SECRET_KEY`.
- Мониторинг: внешний пинг `https://домен/readyz`; метрики Prometheus — `GET /metrics` с заголовком `Authorization: Bearer <METRICS_TOKEN>`.
- Резервное копирование тома `app-data` (файл `vibechat.sqlite`).
- Тексты правил и политики конфиденциальности (`client/src/pages/InfoPages.tsx`) — проверьте с юристом под вашу юрисдикцию.

## Android-приложение (APK)

В папке `android/` — нативное приложение на Kotlin (minSdk 26 / Android 8.0+, targetSdk 35). Оно открывает ваш сервер VibeChat во встроенном WebView, поэтому весь функционал (WebRTC, подбор, чат, жалобы) тот же, что на сайте, и обновляется без новой версии APK. Сверху добавлено нативное:

- системный запрос камеры и микрофона; доступ получает только ваш сервер, остальные сайты — нет;
- если пользователь выбрал «Больше не спрашивать» — подсказка с переходом в настройки;
- полноэкранный режим видео, экран не гаснет во время разговора, громкость регулирует звонок;
- экран ошибки сети с кнопкой «Повторить», кнопка «Назад», внешние ссылки открываются в браузере;
- только HTTPS, cookie не попадают в резервные копии, сторонних библиотек нет.

**Сначала разверните сервер по HTTPS** — без него приложению некуда подключаться. Адрес можно зашить при сборке или ввести в приложении при первом запуске.

### Сборка через GitHub Actions (без Android Studio)

1. Загрузите проект в репозиторий GitHub.
2. Settings → Secrets and variables → Actions → Variables: `VIBECHAT_SERVER_URL=https://ваш-домен`.
3. Actions → «Android APK» → Run workflow. Через несколько минут APK появится в Artifacts.

Для подписанного релиза добавьте секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Создать ключ:

```bash
keytool -genkeypair -v -keystore release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias vibechat
base64 -w0 release.jks   # значение для ANDROID_KEYSTORE_BASE64
```

Храните `release.jks` и пароли в надёжном месте: без них не выпустить обновление в Google Play.

### Сборка локально

Нужны JDK 17+ и Android SDK (проще всего — установить Android Studio и открыть папку `android/`).

```bash
cd android
./gradlew testDebugUnitTest                                   # тесты
./gradlew assembleDebug -PvibechatServerUrl=https://ваш-домен  # app/build/outputs/apk/debug/
```

Для релиза создайте `android/keystore.properties` (не коммитится):

```properties
storeFile=/путь/к/release.jks
storePassword=...
keyAlias=vibechat
keyPassword=...
```

и выполните `./gradlew assembleRelease` (или `bundleRelease` для Google Play).

Название и идентификатор приложения меняются в `android/gradle.properties` (`vibechatAppName`, `vibechatApplicationId`).

### Проверка на эмуляторе

Камера в WebView работает только по HTTPS, поэтому `http://10.0.2.2:8080` не подойдёт. Запустите `npm run dev`, сделайте HTTPS-туннель (`npx cloudflared tunnel --url http://localhost:8080`), добавьте адрес в `EXTRA_ORIGINS` и введите его в приложении. В эмуляторе Android Studio включите виртуальную камеру (Extended controls → Camera).

## Что реально работает

- Гостевой вход после подтверждения 18+ и согласия с правилами; камера запрашивается только по кнопке «Начать».
- Подбор случайного собеседника на сервере: нельзя попасть к самому себе, нельзя оказаться в двух комнатах, повторные клики не создают дубликатов, заблокированные не встречаются, «Следующий» не возвращает того же человека сразу (пауза 10 с).
- Фильтр по языку реально влияет на подбор (точное совпадение в приоритете, «Любой язык» подходит всем).
- WebRTC-видео и звук: offer/answer и ICE через WebSocket, STUN, TURN с временными учётками, ICE restart при обрыве, тайм-аут подключения с автоматическим поиском другого.
- «Следующий» (кнопка и Esc), «Завершить» (камера и микрофон полностью освобождаются), микрофон, камера (собеседник видит, что она выключена), смена фронтальной/основной камеры на телефоне, выбор устройств в настройках, полноэкранный режим (с запасным вариантом для iOS).
- Счётчик времени разговора, статусы «Поиск собеседника», «Подключение», «В сети», «Собеседник отключился», «Восстанавливаем связь».
- Переподключение: при коротком обрыве сети (до 10 с) разговор восстанавливается; собеседник видит «переподключается».
- Работа без камеры (только звук) и понятные экраны при запрете доступа, занятой камере и отсутствии HTTPS.
- Текстовый чат: время, автопрокрутка, пустые состояния, лимит 500 символов, очистка при смене собеседника, серверная очистка невидимых символов, защита от флуда и повторов, доставка только участникам комнаты.
- Жалобы (и на только что ушедшего собеседника), блокировка, автобан после жалоб от нескольких разных людей.
- Админ-панель `/admin`: статистика, жалобы со статусами, бан на срок или навсегда (опционально по сети), снятие банов. Права проверяются сервером на каждый запрос.
- Безопасность: проверка Origin для WebSocket и изменяющих запросов, подписанные httpOnly-cookie, отдельные ключи для гостей и админов, CSP, HSTS, лимиты на подключения, сессии и события, валидация всех событий, логи без IP, SDP, текстов и паролей.
- Количество онлайн — реальные данные сервера.
- Тёмная и светлая темы, адаптивная вёрстка, чат на телефоне — в нижней выдвижной панели.

## Внешние сервисы

- **Обязательно для интернета:** домен с HTTPS; TURN-сервер (свой coturn из `docker-compose.prod.yml` или облачный).
- **По желанию:** Cloudflare Turnstile (защита от ботов), Prometheus/Grafana или UptimeRobot (мониторинг), SMTP/почтовый ящик для поддержки.

## Масштабирование

Один инстанс Node.js держит тысячи одновременных WebSocket-подключений: сервер не передаёт видео, только сигнализацию. Узкие места при росте — TURN-трафик и CPU coturn, их масштабируют отдельно (несколько coturn за DNS).

Для нескольких инстансов приложения понадобится:

1. Перенести очередь и комнаты из памяти (`Hub`, `Matchmaker`) в Redis — с атомарным извлечением пары (Lua-скрипт или `ZPOPMIN`) — и пересылать события между инстансами через Redis Pub/Sub.
2. Реализовать `Storage` поверх PostgreSQL (схема переносится из `001_init.sql` почти без изменений).
3. Включить sticky sessions на балансировщике.

## Известные ограничения и что осталось сделать

- **Проверка возраста** — только самостоятельное подтверждение. Для юрисдикций, где требуется настоящая проверка (документы, сервисы вроде Yoti/Veriff), её нужно встроить в `POST /api/session` перед выдачей cookie.
- **Нет регистрации, профилей и избранных контактов.** Архитектура готова: гостевой идентификатор хранится в подписанном cookie, его можно заменить на идентификатор аккаунта; избранное имеет смысл только с постоянными аккаунтами и согласием обеих сторон.
- **Фильтр по региону не сделан намеренно:** без достоверной геолокации (GeoIP-база и согласие пользователя) он вводил бы в заблуждение. Точка расширения — `languagesCompatible`/`canPair` в `matchmaker.ts`.
- **Модерация только по жалобам.** Автоматического распознавания контента нет — видео не проходит через сервер. Возможное развитие — периодические снимки кадра на стороне клиента с согласия пользователя и отправка на модерацию.
- **Блокировки и баны привязаны к cookie** (и опционально к хешу сети). Очистка cookie обходит бан по гостю; бан по сети это закрывает, но может задеть соседей по NAT.
- **Один инстанс сервера** — см. «Масштабирование».
- **TURN проверен только конфигурацией**: в среде разработки не было coturn, поэтому сквозной тест прошёл с прямым соединением. После развёртывания проверьте звонок между мобильным интернетом и Wi-Fi.
- **`node:sqlite`** в Node 22 помечен как экспериментальный (стабилен в Node 24); предупреждение в логах отключено флагом.
- **`package-lock.json`** не сгенерирован — его создаст первый `npm install`; закоммитьте его для воспроизводимых сборок.
- Платёжной системы нет; платные функции можно добавить на базе аккаунтов.
